GENERAL DRIVER CHANGES
sheetcover.py: candidate selection now optimizes union coverage, rather than
requiring candidates to be mutually disjoint. Binary coverage variables count
each part once. Deterministic assignment removes duplicated placements from
selected sheets; deleting parts preserves feasibility. Coverage/area are
recomputed from actual assigned parts. Unknown IDs and invalid budgets are
handled. Capped group selection prioritizes scarce-part coverage and reports
actual post-truncation counts. --selection-only exports without repacking;
--generate-only checkpoints candidates without later selection/repacking.

sheetcover_repair.py: finite, resumable single-sheet offers with incoming parts
mandatory and optional small fillers. Singles are interleaved across missing
parts and recipients before pairs; bounded pair quota is optional. Logs retain
raw/native placements even when rejected. Checkpoints record instance hash,
actual candidates, missing parts, time/cancellation and rejection reasons.
sheetcover_exchange.py: general two-sheet large-part transfer/swap proposals.
A complete exchange requires both sides and preserved original union. Valid
partial actual subsets are labeled separately and can become pool columns.
sheetcover_hybrid.py: reuse a complete exchange side; warm-repair only its
failed partner from documented baseline transforms. No duplicated cold work.
sheetcover_transfer.py: oriented length/aspect/area ranks elongated-part
transfers; donor removal is feasible by deletion, recipient packs incoming and
transferred parts jointly. --native-seconds enables time mode; --replay-jobs
reuses exact offers. Default iteration mode remains available.
sheetcover_warm.py: finite missing-part x selected-sheet insertion offers,
incumbent transforms retained as movable seeds. rc=0 plus complete expected
part set plus independent geometry checks is required. rc=1 is never success.

sheetcover_pricing.py: fractional-cover dual prices rank new hard cores. Later
LP iterations may use hypothetical columns but original certificate remains
separate; proposed jobs are not inserted into the actual pool without packing.
sheetcover_binplan.py: coordinated exact-once hard-part partitions with area
and count constraints; cached failed attempts are soft evidence, not proofs.
sheetcover_manifest.py: bounded manifest execution and per-result checkpoints.
sheetcover_salvage.py: preserve strict-valid actual subsets from incomplete jobs.
sheetcover_frozen.py (root/native agent): existing fixed-obstacle native fill and
cavity insertion with independent solve/source validation of actual results.
sheetcover_constrained.py: retain supported cores and enumerate a single-plate
transfer enabling a cached residual partition; actual supported columns are
reused and only unsupported cores are emitted as packing jobs.
sheetcover_relocate.py: compose bounded disjoint relocations into actually
supported destinations, emitting only unsupported source cores for packing.
sheetcover_ownership.py: prepare optional-part ownership transfers already
supported by actual columns, freeing a source before warm missing-part insertion.
Each job includes incumbent_partition. A consumer must retain that partition;
ordinary first-owner assignment can otherwise put the transferred part back on
the source and erase the intended free space. Six proposals are saved in
out/rea_small_ownership/jobs.json with adjacent provenance; these older55-based
jobs are superseded by four jobs in out/rea_small_ownership_round4/jobs.json.
sheetcover_warm_manifest.py consumes these explicit partitions, validates both
source and destination geometries and exact preserved union, and checkpoints
all actual columns only after the whole proposed partition passes. Two runner
tests reject missing, duplicate and colliding destination parts. Five ownership
planner tests passed per CNS agent.
sheetcover_jointfill_prepare.py: non-native preparation of disjoint core plus
optional-filler offers. Uses demonstrated co-occurrence and area balancing,
preferring offered load <=90%. Reports unsupported cores explicitly. Supplied
pool membership is evidence only; the preparer does not independently validate
geometry. Actual pack outputs still require the common gate.

VALIDATION AND POLISH
sheetcover_repair.validate_candidate checks solve polygons and, when a real
instance is available, source evaluation polygons. validate_source_candidate
checks the actual subset with quantity one. Mandatory membership, IDs, finite
transforms, holes, intersections, sheet inset and clearance are checked.
sheetcover_polish.py performs bounded translations (normally <=0.5 mm) and
accepts only independently validated results. Source-failure correction adds
small positive padding rather than relaxing clearance/margin. A rejected raw
transfer with gap9.99998512696 and margin14.9996699433 stayed excluded because
bounded correction failed. Engine quality flags alone are not acceptance.
validate_strict.py separately checks all source-polygon pairs, including parts
inside holes, margin15, clearance10, completion and optional sheet limit.
Distance tolerance is1e-6 mm; overlap-area tolerance is1e-8 mm2. Legacy
evaluate.py thresholds were not weakened or replaced. Optional external curve
error bounds are conditional and are not verified by the strict script.

NATIVE API
src/nest_physics_cpp/nest_physics_capi.h/.cpp exports np_nest_warm_one.
It follows np_nest arguments, with warm_present, warm_tx, warm_ty, warm_angle
inserted after part_rotations. Seeds use public sheet-local output coordinates.
Exactly one sheet; offered incumbents remain movable; all offered parts must
fit for success. rc0=complete clean repair; rc1=no repair/cancel; rc2=bad input.
Fallback preserves seed entries and leaves incoming parts unplaced. Fallback
quality is unverified, not clean. Existing exports and NpParams layout remain.
tools/bench3dm/engines.py solve_np_warm binds lazily, validates finite seeds and
unknown IDs, and supports part IDs or (part ID,copy index). Pool drivers require
quantity one. NP_WARM_WORKERS limits warm native threads; NP_WORKERS controls
ordinary single-start pool parallelism; NP_STARTS_WORKERS remains multistart.
