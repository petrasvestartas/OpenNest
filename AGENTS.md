# Project naming

Use OpenNest naming for maintained project source, namespaces, targets,
filenames, interfaces, UI text, documentation, and future generated outputs.
Apply naming changes incrementally and update build scripts, imports, and
references together. Verify the affected build or workflow after migration.

Keep third-party binaries, required notices, original-source attribution, and
immutable verification records identifiable in the separate reference archive.
Do not rewrite historical evidence or imply that renaming changes provenance.
Keep reference-only paths out of portable production code and user interfaces.

Prioritize the native C++ solver and the complete five-sheet benchmark before
Grasshopper and UI work. Preserve unrelated local changes.
